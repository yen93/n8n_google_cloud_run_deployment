AUTOMATIONS / ROUTINES
- Scheduling approach (chosen 2026-09-14): n8n's in-process Schedule Trigger does
  NOT run on Cloud Run because min-instances=0 scales the container to zero after
  ~15 min idle and the scheduler only runs while a container is alive. Replaced by
  external HTTP calls to per-workflow Webhook Trigger URLs, driven by Supabase
  pg_cron + pg_net (fully free, in-stack). Each daily job fires an HTTP GET that
  both wakes the container and triggers the workflow.
- LIVE cron jobs (cron.job in Supabase, verified 2026-09-14): 11 active, ALL
  once-daily, staggered ~7:00-9:30 AM Manila (stored as UTC; pg_cron runs in UTC,
  no DST). Two share the 9:30 AM slot (n8n-sales-daily-email-notification and
  "Insta Story Scraper: Log to sheet and notify Liv"). All fire an HTTP GET to a
  webhook, which both wakes the container and triggers the workflow.
  - The 2 intraday-recurring jobs (Email Handling Agent every 5 min, Action Items
    Automation every 15 min, 7 AM-4 PM) were REMOVED — those workflows were moved
    to a local Docker n8n. This is what dropped the cost (no more ~9 h/day uptime).
  - Discrepancy to reconcile: the live set does NOT include
    n8n-linkedin-outbound-sales (LinkedIn Outbound Sales, 7:00 AM) — either not
    added or later removed; confirm if it should be scheduled.
- scripts/schedule_webhooks.sql (repo root) — the reference script that created
  the jobs. STALE vs live: it still contains the intraday section (Email Handling
  Agent / Action Items) which is no longer wanted, and its 12th daily job is named
  n8n-insta-story-scraper-log-notify-liv (live job uses the friendly name). Re-run
  it only after pruning the intraday section, or it will recreate the dead jobs.
- COST (Cloud Run, always-allocated 1 vCPU + 1 GiB): now that only once-daily jobs
  remain, container uptime is minimal (~daily 7-9:30 batch), so ~$0-3/month
  (mostly within the free tier). Was heading to ~$12-18/month with the intraday
  jobs. Verified via billable_instance_time metric (~10 instance-hours MTD as of
  2026-09-14).
- Webhook trigger URLs for the workflows are listed in `n8n webhooks.txt`
  (repo root) — 14 listed as of 2026-09-14 (includes the 2 now-local intraday
  ones). They are Authentication=None (public, GUID-path, unauthenticated) —
  anyone with a URL can trigger the workflow. No token stored.
- Legacy: the original 29 schedule triggers across the 13 formerly-active
  workflows were disabled during the 2026-09-11 migration; workflows re-activated
  with Webhook Triggers per the above.
