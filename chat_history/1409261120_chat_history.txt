USER:
Two questions (no implementation): (1) Is a webhook trigger better/cheaper than a
schedule trigger? (2) Can we call webhooks for free via Supabase or another service?

--------------------------------------------------------------------------------
ASSISTANT:
Answered:
1. Webhooks are NOT cheaper — Cloud Run cost is driven by container awake-time,
   which is a similar short daily burst either way. Either approach still needs an
   EXTERNAL caller because a scaled-to-zero container can't wake itself. The webhook
   is the cleaner design (one HTTP call both wakes and triggers, no cron-vs-sleep
   race, caller controls timezone); its cost is the exposed public URL and the need
   to edit the workflow.
2. Free schedulers: Supabase pg_cron + pg_net (fully free, in-stack, runs in UTC);
   Google Cloud Scheduler (3 free jobs, native, per-job timezone). Also Cloudflare
   Workers cron, cron-job.org, GitHub Actions (best-effort, imprecise), UptimeRobot.
   Recommended Cloud Scheduler or Supabase pg_cron.

Checked pg_available_extensions: pg_cron 1.6.4, pg_net 0.20.4, http 1.6 all

UTC, no DST, so 10:05 Manila = 02:05 UTC = '5 2 * * *'; (5) verify via cron.job,
cron.job_run_details, net._http_response; (6) n8n side — Webhook Trigger node with
Header Auth. Flagged pg_net is async fire-and-forget (check net._http_response for
the real status) and that cold starts are slow.
