n8n Automations — User Guide

n8n is the tool the MAG team uses to build and run automated workflows — things like follow-up email sequences, lead scraping, and syncing data between ActiveCampaign, Gmail, Google Sheets, and other services. It now runs in the cloud (Google Cloud Run) instead of on a single office computer, so your automations and credentials live in one shared, always-available place. This guide explains how to log in, build and run workflows, and what to expect.

What This Is

n8n is a visual workflow builder. Each workflow is a chain of steps ("nodes") that connect apps and move or transform data automatically — for example, "every morning, pull new leads, enrich them, and draft follow-up emails." You build workflows by dragging nodes onto a canvas and connecting them, no coding required for most tasks.

Everything you create — workflows, credentials, and settings — is stored in a shared cloud database, so it is the same for everyone on the team and is not tied to any one person's laptop.

Who This Guide Is For

The MAG team members who log into n8n to create, edit, and run workflow automations. You do not need to be a developer, but you should be comfortable with the apps your workflows connect to (ActiveCampaign, Gmail, Google Sheets, etc.).

How to Use It

  1. Open n8n in your browser: https://n8n-659687081407.australia-southeast1.run.app
  2. Sign in with your n8n account. If this is the very first time anyone has opened the instance, n8n will ask you to create the owner account (email + password) — this is a fresh login, separate from any old local n8n login.
  3. Find a workflow from the Workflows list on the left, or click Add workflow to start a new one.
  4. Build or edit by adding nodes to the canvas and connecting them. Click any node to configure it.
  5. Connect an app the first time you use it by adding a credential (for example, signing into Gmail or ActiveCampaign). Credentials are saved and reused across workflows.
  6. Test a workflow with Execute workflow to run it once manually and see the result of each step.
  7. Turn it on by toggling the workflow Active (top right) when you are ready for it to run on its schedule.
  8. Save your changes. Edits save straight to the shared database — there is nothing to deploy or re-publish.

What to Expect

  • Your changes are live immediately. Editing a workflow, adding a credential, or changing a setting takes effect right away for everyone — no redeploy needed.
  • Scheduled workflows run on a fixed daily schedule set up by your automations admin (see Known Limitations for why scheduling is handled specially).
  • The site may take a few seconds to load if no one has used it recently. The service "sleeps" when idle to keep costs at zero and wakes on the first visit — the first page load or first run of the day can be slow, then it is fast.
  • Execution history is kept for 14 days and then automatically cleared, so you can review recent runs but not old ones.

How the Daily Trigger Works

Because the n8n service sleeps when idle, it can't reliably wake itself up to run a scheduled job. So the "alarm clock" lives outside n8n, in the Supabase database, and it works like this:

  1. A daily cron entry exists for each workflow. Supabase includes a free scheduler called pg_cron. For every workflow above there is one cron entry — essentially a line that says "at this exact time every day, run this task." For example, the Soc Med Follow Up Sequence entry means "every day at 7:15 AM Philippine time."
  2. At the set time, the cron entry fires. pg_cron runs its small task automatically, every day, without anyone touching it.
  3. That task sends a web request to the workflow's webhook. The task uses another free Supabase tool called pg_net to make an HTTP call to that workflow's unique Webhook Trigger URL in n8n.
  4. The request wakes n8n and starts the workflow. The incoming call wakes the sleeping Cloud Run service (if needed) and n8n's Webhook Trigger node begins running the workflow's steps.

In short: Supabase's daily cron → sends a web call → n8n's Webhook Trigger → the workflow runs.

A note on time zones: pg_cron keeps its schedule in UTC (not Philippine time), so each Philippine time above is stored as its UTC equivalent behind the scenes — for example, 7:15 AM Philippine time is saved as 23:15 UTC the day before. Your automations admin handles this conversion; you only need to think in Philippine time.

Known Limitations

  • Scheduling is not done inside n8n. Because the service sleeps when idle to stay free, n8n's own built-in "Schedule Trigger" will not fire while the service is asleep. Instead, scheduled workflows use a Webhook Trigger that an external free scheduler (Supabase) calls at the set time each day. If you need a workflow to run on a schedule, ask your automations admin to wire it up this way rather than relying on the Schedule Trigger node.
  • Times are handled in UTC / Sydney behind the scenes. When setting or discussing schedule times, confirm the intended timezone — the server's default is Sydney time and the external scheduler uses UTC, which is not the same as Philippine time. Your admin translates these for you.
  • Google logins may need re-connecting. After the move to the cloud, Google-based credentials (Gmail, Drive, Docs, Sheets) may need to be re-authorized once. If a Google node errors on auth, reconnect its credential.
  • No email/notification when a run fails unless a workflow was specifically built to send one. Check a workflow's Executions tab to confirm it ran.

How It Was Built (Architecture & Tech Stack)

The instance was migrated from a local Docker setup on an office PC to a fully cloud-hosted setup, so it no longer depends on any one machine being on.

  • n8n (v2.22.6) — the workflow automation app itself, packaged as a container image with a set of extra community nodes baked in.
  • Google Cloud Run — runs the n8n container serverlessly; it scales to zero when idle (which is why it "sleeps") to keep cost at $0.
  • Supabase (PostgreSQL) — the shared cloud database that stores all workflows, credentials, and settings, on the free tier.
  • Google Secret Manager — securely stores sensitive keys (the encryption key and database password) so they are never hard-coded.
  • Supabase pg_cron + pg_net — a free, database-driven scheduler that calls workflow webhooks at set times each day, replacing n8n's built-in scheduler.

The daily flow: the Supabase scheduler calls a workflow's webhook at its set time → this wakes the Cloud Run service and triggers the workflow → n8n runs the steps and reads/writes data in Supabase and the connected apps.

Troubleshooting

  • The site won't load or is very slow: it was probably asleep — wait a few seconds and refresh. The first load after a quiet period is always the slowest.
  • "Offline / No network connection" banner and can't save: refresh the page; if it persists, contact your admin (this was a known infrastructure issue that has been fixed, so it should not recur).
  • A scheduled workflow didn't run: check that it is toggled Active, and confirm it uses a Webhook Trigger wired to the external scheduler — the built-in Schedule Trigger will not fire reliably on this setup. Also double-check the intended timezone.
  • A Google/Gmail/Sheets step fails with an authorization error: its credential likely needs re-connecting — open the credential and re-authorize it.
  • You can't tell if a workflow ran: open the workflow and check its Executions tab (history is kept for 14 days).
